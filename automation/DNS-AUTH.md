# Email domain authentication for jparkassociates.com (Brevo)

One-time DNS setup so The Monthly Close sends as `@jparkassociates.com` and
lands in the inbox. Do this at whoever hosts your DNS (the registrar or, if
you use Google Workspace, possibly the same admin console).

> ⚠️ `jparkassociates.com` is already sending your day-to-day mail (Google
> Workspace / Gmail). **Do not replace existing records.** SPF and DMARC each
> allow only **one** record per domain — you *merge* into what's there. Getting
> this wrong can break your normal email, so check the current records first.

## 0. Check what already exists (before touching anything)

```bash
dig +short TXT jparkassociates.com          # look for an existing v=spf1 record
dig +short TXT _dmarc.jparkassociates.com    # look for an existing v=DMARC1 record
```

Note whatever comes back — you'll extend it, not overwrite it.

## 1. DKIM + domain verification — values come from Brevo

In Brevo: **Senders, Domains & Dedicated IPs → Domains → Authenticate**. Brevo
shows you the exact records to add — typically:

- a **DKIM** record (a TXT/CNAME at a Brevo-provided host like
  `mail._domainkey.jparkassociates.com`), and
- a **domain-verification** TXT at the root (`brevo-code:...`).

These are **account-specific and generated by Brevo** — paste the exact values
from that screen. (When you're at this step, send me the panel and I'll help you
transcribe them correctly.) Then click **Verify** in Brevo.

## 2. SPF — MERGE, do not replace

- **If an SPF record already exists** (very likely, e.g. it contains
  `include:_spf.google.com`), add Brevo's include to the *same* record:

  ```
  v=spf1 include:_spf.google.com include:spf.brevo.com ~all
  ```

- **If no SPF record exists**, add one TXT record at the root (`@`):

  ```
  v=spf1 include:spf.brevo.com ~all
  ```

Never create a second SPF record — two `v=spf1` records is an error and hurts
deliverability.

## 3. DMARC — add if missing, don't downgrade if present

- **If no DMARC record exists**, add a TXT at `_dmarc.jparkassociates.com`,
  starting in monitor-only mode:

  ```
  v=DMARC1; p=none; rua=mailto:postmaster@jparkassociates.com
  ```

  Let it run a few weeks, confirm Brevo mail passes, then tighten to
  `p=quarantine` and eventually `p=reject`.

- **If a DMARC record already exists**, leave its policy as-is — just make sure
  SPF (step 2) and DKIM (step 1) are aligned so Brevo mail passes it. Don't
  loosen an existing `p=quarantine`/`p=reject`.

## 4. Verify

- Click **Verify / Authenticate** in Brevo until DKIM, SPF, and the domain
  code all show green.
- Send yourself a test campaign and check the received headers show
  `DKIM=pass`, `SPF=pass`, `DMARC=pass`.

## Summary

| Record | Host | Value | Source |
|---|---|---|---|
| DKIM | Brevo-provided (e.g. `mail._domainkey`) | Brevo-provided key | **From Brevo** |
| Verification TXT | `@` | `brevo-code:...` | **From Brevo** |
| SPF (TXT) | `@` | merge `include:spf.brevo.com` into the existing `v=spf1` | Fixed (mergeable) |
| DMARC (TXT) | `_dmarc` | `v=DMARC1; p=none; rua=mailto:postmaster@jparkassociates.com` | Fixed (add if missing) |

Once all three pass, set `sender`/`replyTo` in `automation/brevo.config.json` to
a real `@jparkassociates.com` address and continue the go-live checklist in
`automation/SEND.md`.
